# Limitations — Balloon Rally v0.1

This page is deliberately blunt. v0.1 is a playable browser + Tauri-shell vertical slice, not a finished product.

## Deliberate product limits

- **6 players is supported but 2–4 is the sweet spot.** The engine, setup, scoreboard, and support panel handle 2–6. Six-player rows are denser and the table is tuned visually for 2–4. This is the “clear scaling” trade-off from the brief.
- **One tailwind per round.** Because each seat makes one support choice per round, the two tokens can be used in two different rounds, not both at once. This keeps the choice readable for an 8-year-old.
- **Final +5 uses round-4 support.** Supporters of the overall leader are the players who backed that balloon in the final round. Earlier support does not pay again. See `docs/rules.md`.
- **No finish bonus.** Space 20 is a cap; the highest position after four rounds is the overall leader. This avoids a second scoring subsystem.
- **Shared wins are possible.** If total, correct supports, and remaining tailwind all tie, the ranking shares first place. Stats count a win for each shared winner.
- **Privacy cover is social, not cryptographic.** It hides the panel visually and the engine view strips other supports. On LAN the host keeps the full state and sends each guest only `view(state, guestSeat)`, so hidden supports never go over the wire; a guest still shares one device with its own eyes. This is a family game, not a tournament server. LAN games are session-only and are not written to the browser save.
- **LAN seats are human guests.** The LAN lobby does not fill empty seats with AI; solo AI is a separate mode. A disconnected guest keeps the seat and can reconnect, but there is no 12-second AI takeover yet.
- **Sound is synthesized.** There are no recorded audio assets in the app; Web Audio tones are generated locally. Muted play is fully supported.
- **The screenshot states are curated.** `?demo=summary|support|end` builds a deterministic real engine state for screenshots. The screenshots are still from the running app, not mockups.
- **Stats export is a download.** There is no clipboard fallback; if the browser blocks downloads, the stats remain visible on screen.
- **Video audio is synthetic + procedural.** Narration is Edge TTS, the bed and chimes are generated by `video/scripts/gen-audio.mjs`, and the final cuts are mastered to −14.05 / −14.08 LUFS with true peaks −1.42 / −1.49 dBTP. It has not been through a human voice performance or a broadcast QC pass.

## What is already solid

- Pure deterministic engine with seeded RNG, immutable apply, invariants, stable error codes, versioned serialization, and replay.
- 120 seeded complete simulations, 47 unit/integration tests, `tsc`, production build, real E2E, and a real LAN host/guest E2E with hidden-view and reconnect checks.
- Hidden support and wind information removed in `view`, not merely hidden in CSS; LAN guests receive only their own filtered view.
- Four AI levels in a Web Worker with an ≤80 ms budget; Companion favourite-balloon avoidance.
- 2–6 player setup, privacy cover, hints, undo, autosave/resume, replay, stats, JSON export, bilingual UI, keyboard path, reduced motion, muted play, and portrait layout.
- Real 1440×1000 LAN and game screenshots, 390×844@2× mobile screenshots; Remotion 45 s cuts in English and Chinese, bilingual posters, SRTs, and a loudness-mastered audio report.
