# Gomoku · known limitations (v0.1)

- **Freestyle only.** This is the 15×15 freestyle variant requested by the brief:
  overlines count and there are no forbidden moves or Renju opening rules.
- **Hard is not a tournament engine.** It runs a six-ply threat-space search with
  a deterministic node cap (14,000 nodes). It sees immediate wins, fours, open
  threes and many forced sequences, but it can miss very deep victory-by-
  continuous-four lines or subtle double-threat defences.
- **Two players only.** The engine and UI are built around Black and White. There
  is no spectator mode; a second guest receives “room full”.
- **LAN is local-subnet IPv4.** There is no matchmaking, internet play, account or
  cloud relay. The four-digit room code keeps honest family members out; it is not
  a security boundary.
- **Browser-hosted QR needs the relay.** In a plain Vite dev page the invite points
  at port 8080. Build first and serve with `npm run lan`, or use the Tauri build,
  which starts the bundled relay.
- **Stats are per device.** A LAN game is recorded on the host, not duplicated on
  the guest. Clearing the record only affects the current browser/device.
- **Undo after resume starts a fresh history.** The autosave stores the position,
  mode and level, not every previous position, so an immediate undo after resuming
  a saved game is unavailable until the next move.
- **No 4K or vertical promo.** `video.json` is a manifest for the root studio; this
  app does not contain a separate Remotion project or pre-rendered video.
- **No cloud, accounts, ads or telemetry.** Sound is synthesised locally; art is
  drawn in CSS and the board is generated by the app.
